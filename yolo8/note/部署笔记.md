### 1.5 关键脚本调用关系

```
run_tracker.py
 ├─ GStreamerWrapper.GetFrame()              后台线程 pull-sample → 640×360 BGR
 ├─ RobotController.Run(frame)
 │   ├─ YoloWrapper.Track(frame)
 │   │    └─ ultralytics YOLO(engine).track(persist=True, classes=[0], conf=0.5)
 │   ├─ FindTarget(results[0].boxes)         按 track id 匹配锁定目标
 │   ├─ TrackAndDraw(...)                    解算 v / ω → ROS2Transfer.SendCmdVel → /cmd_vel
 │   └─ NonTrackAndDraw(...)                 未锁定时只画框、显示 Stop
 └─ cv2.imshow("DR People Tracking", ...)    ESC 退出
```

控制律（详见另文）：`ω = -(cx/W - 0.5) × 2 × 1.2`；`top = y1/H`，`top<0.25` 时 `v = 5·top - 0.2·v_prev`，否则 `v = 1.0`。

### 1.6 多种 YOLO 实现方式的差异与推荐

| 差异点 | 选项 | 推荐 | 理由 |
|---|---|---|---|
| 工程 | `lite_cog`(ROS1) / `lite_cog_ros2`(ROS2) | **ROS2** | 算法完全一致，仅 ROS 后端不同；103 默认 source Foxy |
| 权重 | `_arm.engine` / `_amd.engine` | **`_arm.engine`** | 103 是 ARM Jetson；`_amd.engine` 为 x86 导出，本机加载失败 |
| 入口 | `run_tracker.py` / `test/yolov8.py` | 验证用 headless 脚本；运行用 `run_tracker.py` | `test/yolov8.py` 依赖 `/dev/video0`（本机无）+ amd.engine + 有 sys.path 缺陷 |

### 1.7 原项目前置条件缺失（复刻时已补齐）

1. **无 `requirements.txt`**：依赖全靠 JetPack 预装，换机器极易缺失。→ 本笔记第六节给出完整版本清单。
2. **无启动脚本**：靠人工 `cd` 到正确目录。→ 本笔记第五节给出标准化命令。
3. **`test/yolov8.py` 有 import 缺陷**：脚本在 `src/test/` 下运行时 `sys.path[0]` 是 `test/`，找不到 `src/ultralytics`；改从 `src/` 运行则相对路径 `../../model/` 又失效。两难。→ 复刻版验证脚本用 `__file__` 显式补 `sys.path` 解决。
4. **`test/yolov8.py` 用 `_amd.engine`**：在 ARM 机器上必然失败。→ 复刻版改用 `_arm.engine`。
5. **engine 跨设备警告**：加载时出现 `Using an engine plan file across different models of devices is not recommended`，说明该 engine 并非在当前这台 Xavier 上导出（同型号另一台或早期导出）。当前**能正常工作**，但在同类机器部署时建议用 `export_engine.sh` 现场重新导出。

## 三、遇到的报错、根因与解决办法

| # | 报错 | 根因 | 解决办法 |
|---|---|---|---|
| 1 | `ModuleNotFoundError: No module named 'ultralytics'`（在 `src/test/` 下运行脚本） | Python 执行脚本时 `sys.path[0]` 是**脚本所在目录**（`test/`），不是 cwd；而 `ultralytics` 在 `src/` 下 | 脚本内 `sys.path.insert(0, os.path.abspath(os.path.join(os.path.dirname(__file__), "..")))`。**原项目 `test/yolov8.py` 缺这一步**，故换个目录跑必失败 |
| 2 | （预期）`_amd.engine` 在 103 上加载失败 | `yolov8n_amd.engine` 是 x86/AMD 机器导出的 TensorRT 引擎，与 Jetson ARM 架构不兼容 | 本机一律使用 `yolov8n_arm.engine`；`test/yolov8.py` 若要在本机跑需改为 arm 版 |
| 3 | `[TRT] [W] Using an engine plan file across different models of devices is not recommended` | engine 计划文件非当前设备导出（同型号另一台或早期导出） | 当前**可正常工作**；若追求最优性能或换机器，用 `model/export_engine.sh` 现场重新导出 |
| 4 | （潜在）`cp` 复制后残留 `__pycache__` 含旧路径 | 编译缓存记录了原路径 | 复制后统一 `find ... -name __pycache__ -exec rm -rf {} +` |
| 5 | （潜在）换机器缺少 torch/tensorrt | 原项目无 `requirements.txt`，依赖靠 JetPack 预装 | 按第六节版本清单核对；Jetson 需装 JetPack 对应 torch（`2.1.0a0+nv23.06`），不可用 pip 通用版替代 |

## 八、双通路发布（RTMP + Foxglove/ROS2）

在纯推理部署之上，把标注后的视频帧同时对外提供两种消费方式。
**完整踩坑细节见同目录 `双通路发布-踩坑记录.md`**，本节只做索引。

### 8.1 两条通路

| 通路 | 链路 | 消费端 | 编码代价 |
|---|---|---|---|
| RTMP | `appsrc → nvvidconv → nvv4l2h264enc → flvmux → rtmpsink` | VLC / ffplay / 网页播放器 | **硬件编码**，几乎不占 CPU |
| Foxglove | `cv2.imencode → CompressedImage → rosbridge(ws://:9090)` | Foxglove Studio | JPEG 软编，默认每 3 帧发一次 |

### 8.2 新增/改动文件

- 新增 `src/RtmpPublisher/RtmpPublisher.py` — GStreamer 硬编推流封装
- 新增 `src/run_tracker_publish.py` — 双通路主入口（**不改动**原 `run_tracker.py`）
- 改动 `src/RobotController/ROSTransfer/ROS2Transfer.py` — 新增 `SendImage()`（原文件已备份为 `ROS2Transfer.py.bak-20260921`）
- 新增 `src/test/verify_rtmp_link.py`（L1/L3）、`verify_ros2_publish.py`（L2）、`verify_foxglove_path.py`（L4）
- 新增 `logs/` 运行日志目录、`note/双通路发布-踩坑记录.md`

### 8.3 实测结果（已全部通过）

- RTMP 真实推流 + `ffprobe` 回拉：`h264 / 640×360 / 30 fps`
- ROS2：`ros2 topic hz /yolo/image_annotated` ≈ **8 Hz**
- Foxglove 通路（手写 WS 客户端直连 rosbridge）：8.17 Hz，`format=jpeg`，`frame_id=camera`
- 端到端稳态 **22 ~ 26 fps**，单核 ~80% CPU

### 8.4 关键坑位索引

1. `nvv4l2h264enc` 只吃 `video/x-raw(memory:NVMM)` → 必须先 `nvvidconv`
2. Python 里 `rtmpsink location="URL live=1"` 必须加**真引号**（shell 能过不代表 Python 能过）
3. RTMP 连不上时 `push-buffer` 仍返回 OK → 必须监听 GStreamer **总线**消息
4. `ros2 topic hz` 收不到 = QoS 不匹配 **+** 输出块缓冲，两个原因
5. Foxy `logger.info()` 只接受单字符串
6. headless 下 `RobotController.InputAndProcess()` 里的 `cv2.waitKey` 会抛异常 → monkey-patch
7. `Run()` 无检测结果时返回 `None` → 跳过而非退出
8. `cv2.UMat` 需 `.get()` 才能 `imencode`
9. 长前台 SSH 会被掐断 → `setsid nohup` + 工程内 `logs/`（`/tmp` 会被清）
10. 冷启动约 35 s（TRT 加载 + RTSP 首帧），`Stream format not found` 属启动期噪声

### 8.6 四个常备脚本（2026-09-22 追加）

日常只需这四个，底层都调 `lite3-publish-ctl.sh`（无重复逻辑）：

| 脚本 | 作用 | sudo |
| --- | --- | --- |
| `./start.sh [yolo\|rosbridge\|all]` | 启动（不开机自启），模式为 dual/ros2 时自动带 rosbridge | 否 |
