# 05 · 网络与出网配置（103 专用）

**适用场景**：103 拉不到包、断网、GitHub 连不上、apt 报错，或新主机需要打通出网链路。

## 拓扑要点（必须先理解）

```
103 (<HOST_103>) ──默认路由 via──> 120 (<HOST_120>) ──wlan0──> 外网
```

**103 的出网完全依赖 120 做 MASQUERADE。** 120 一重启，103 就断网。

## 操作步骤

### 1. 判定：是不是 NAT 掉了

```bash
ping -c2 <SRS_HOST>          # 103 上
ssh <SSH_ALIAS_120> 'ping -c2 <SRS_HOST>'
```

**120 通、103 不通 → 九成是 NAT 规则没了。**

### 2. 修复（在 120 上执行，立即生效）

```bash
printf "\047\n" | sudo -S iptables -t nat -A POSTROUTING -s <LAN_NET> -o wlan0 -j MASQUERADE
```

### 3. 持久化（120 上，否则重启即失效）

把上面那行追加进 `/home/ysc/host/host_start2.sh`（由 `host.service` 开机执行）。
已存在于 2026-09-23 追加过一次，若再次断网先检查该脚本是否被还原。

### 4. 检查 NAT 与连通

```bash
# 120 上
printf "\047\n" | sudo -S iptables -t nat -S POSTROUTING | grep <LAN_NET>

# 103 上
ip route | grep default                 # 期望 via <HOST_120>
cat /etc/resolv.conf                    # 期望 223.5.5.5 / 119.29.29.29
curl -sL http://<SRS_HOST>:1985/api/v1/streams/    # SRS 流列表（必须 -L）
```

### 5. GitHub 与 apt 源

```bash
# 代理（本机 Windows 的 Clash mixed 端口，实测 clone 约 4m29s）
export http_proxy=http://<PROXY_HOST>:7897 https_proxy=http://<PROXY_HOST>:7897

# 或镜像
git clone https://gh-proxy.com/https://github.com/<owner>/<repo>.git

# apt 源：不要使用清华 ubuntu-ports（实测 403），用 ports.ubuntu.com
```

## 关键配置文件路径

| 文件 | 作用 |
|---|---|
| `/home/ysc/host/host_start2.sh`（120） | 开机脚本，含 NAT 持久化行 |
| `/etc/iptables/rules.v4`（120） | 静态规则（**无 netfilter-persistent，不会自动恢复**） |
| `/home/test/net/readme` | 早期 NAT 排障记录 |
| `/etc/apt/sources.list.d/*.list` | apt 源 |
| `/etc/apt/apt.conf.d/01proxy` | apt 代理（需要时创建） |
| `~/.gitconfig` | `http.proxy` 可在此持久化 |
| `/etc/resolv.conf`（103） | DNS |

## 验证方法

```bash
ping -c2 <SRS_HOST>                       # 通 = 出网正常
curl -sI https://github.com --max-time 10    # 不配代理通常超时（属预期）
timeout 5 bash -c "cat < /dev/null > /dev/tcp/<HOST_120>/22" && echo "120 ssh ok"
```

## 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 103 ping 外网全不通，120 通 | 120 缺 <LAN_NET> 的 MASQUERADE | 按第 2 步补规则 |
| 重启 120 后 103 又断网 | NAT 未持久化 | 写进 `host_start2.sh` |
| `git clone` 卡住 | 直连 GitHub 443 超时 | 走代理 / gh-proxy / 本机 scp |
| `apt-get update` 非 0 退出 | 清华镜像 403 | 换 `ports.ubuntu.com` |
| IPv6 不通 | 103 无全局 IPv6 地址与默认路由（**预期行为**） | 无需处理 |
| 推流卡在 SYN-SENT | 出网断了 | 先恢复 NAT，再 `restart` 推流服务 |
| 网络状态反复变化 | 120 的 WiFi/热点会波动 | 判"没网"前必须实时复测，别沿用旧结论 |

## 回滚方式

```bash
# 120 上删除误加的规则（把 -A 换成 -D）
printf "\047\n" | sudo -S iptables -t nat -D POSTROUTING -s <LAN_NET> -o wlan0 -j MASQUERADE
```

改 `host_start2.sh` 前先备份：`cp host_start2.sh host_start2.sh.bak-$(date +%Y%m%d)`，并 `bash -n` 做语法检查。
