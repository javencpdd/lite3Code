### P6 · 环境隔离脚本 `scripts/env.sh`（关键，防 ROS 1/2 串味）

103 的 `~/.bashrc` 默认 `source /opt/ros/foxy/setup.bash`，直接开 shell 编译会串环境。`env.sh` 需做到：

```bash
#!/bin/bash
# 1) 清掉可能的 ROS 2 环境变量
unset AMENT_PREFIX_PATH COLCON_PREFIX_PATH ROS_VERSION ROS_PYTHON_VERSION
export PYTHONPATH=$(echo "$PYTHONPATH" | tr ':' '\n' | grep -v '/opt/ros/foxy' | paste -sd:)
# 2) 只加载 ROS 1 Noetic
source /opt/ros/noetic/setup.bash
# 3) 加载本工作空间（编译出 devel 之后才有）
source /home/test/scan_planner/devel/setup.bash 2>/dev/null
export ROS_MASTER_URI=http://127.0.0.1:11311
export ROS_IP=192.168.1.103
echo "[env] ROS_DISTRO=$ROS_DISTRO ($(rosversion -d))"
```

校验：执行后 `rosversion -d` 必须输出 `noetic`，`echo $AMENT_PREFIX_PATH` 必须为空。

## 2. 编译（D）

```bash
ssh lite3-f20-1-103
cd /home/test/scan_planner
source scripts/env.sh
catkin_make -j2 -DCMAKE_BUILD_TYPE=Release 2>&1 | tee logs/build_$(date +%m%d_%H%M).log
```

要点：

| 项 | 建议 | 原因 |
|---|---|---|
| 并行度 | 先 `-j2`，观察内存后最多 `-j3` | 6.7 GiB 内存 + PCL/OpenCV 头文件极重，`-j6` 大概率 OOM 或触发 OOM-killer 干掉现有服务 |
| GPU 选项 | **不加 `-DUSE_GPU=ON`** | 走默认 CPU 版 `pcl_render_node`；GPU 版在 Jetson 上需桌面 OpenGL + glfw3（未装），CMake 会直接 FATAL_ERROR |
| 编译标准 | 源码自带 `-std=c++11 -std=c++14` | 无需干预 |
| 预计耗时 | 10~25 分钟（10 个 C++ 包，含 ikd-Tree、FOV_Checker） | 建议用 `run_in_background` 方式跑，避免 SSH 超时中断 |
| 断点续编 | `catkin_make` 支持增量 | 失败修好后重跑同一条命令即可 |

```bash
                     #   /quad_0/body_pose、/planning/bspline、/cmd_vel、/planning/data_display
```

发目标点（navi_mode 1 用 RViz 2D Goal，无 GUI 时直接发话题）：

```bash
rostopic pub /move_base_simple/goal geometry_msgs/PoseStamped \
 '{header: {frame_id: "world"}, pose: {position: {x: 5.0, y: 0.0, z: 0.3}, orientation: {w: 1.0}}}'
# 随后观察 /planning/bspline 是否开始输出、/cmd_vel 是否有非零 Twist
```

通过判据：

- [ ] `/planning/bspline` 有持续输出（说明 FSM + 前端搜索 + B 样条优化跑通）
- [ ] `/cmd_vel` 出现非零速度且随后收敛（说明闭环控制器工作）
- [ ] 无 `ROS_ERROR` 刷屏，`scan_planner_node` 未崩溃


## 4. 阶段二：真机接入（Lite3）

> 前置：阶段一 V2 全绿；且已确认机器人处于安全状态（架空/低速/有人值守）。

### 4.1 ROS 1 ↔ ROS 2 桥接（核心难点）

103 的实时数据在 ROS 2（foxy）侧，规划器在 ROS 1（noetic）侧。三种做法：

| 方案 | 做法 | 优点 | 代价 |
|---|---|---|---|
| **A（推荐）ros1_bridge** | `sudo apt install ros-foxy-ros1-bridge` | 通用、后续可复用；**实测 ROS 源有 arm64 候选包 0.9.7，可直接装，无需离线折腾** | 需注意 bridge 默认只桥接内置消息类型，自定义 msg 要单独配置 |
| B 轻量中继 | 自写一个 ROS 2 节点订阅 + ROS 1 节点发布（进程内 socket/共享内存） | 不依赖 bridge 包 | 自研维护成本，通用性差 |
| C 全面 ROS 2 化 | 把 planner 移植到 Foxy | 与现有栈统一 | 社区版是 Humble/C++17，回迁 Foxy 工作量大，不适合第一步 |

桥接话题映射建议（**注意改名避让**）：

| ROS 2（foxy，103 现有） | → | ROS 1（noetic，规划器） | 备注 |
|---|---|---|---|
| faster_lio `/Odometry`（需先启动 slam 工作空间） | → | `/LIO/odom_vehicle` | 机体位姿 |
| faster_lio IMU 里程计 / `/imu/data` 派生 | → | `/LIO/odom_imu` | 传感器位姿 |
| `/rslidar_points` 或 mid360 点云 | → | `/LIO/clouds_lidar` | 需确认当前实际使用的雷达（103 同时有 leishen/mid360 驱动） |
| `/scan_planner/cmd_vel` (ROS 1) | → | 机器人指令口（先不直连 `/cmd_vel`） | **安全避让**：ROS 2 侧 `/cmd_vel` 已被 transfer 订阅 |

关键提醒：

- 实测当前 ROS 2 话题列表中**没有** faster_lio 的输出（`/Odometry`、`/cloud_registered` 等），说明 slam 未运行 → 阶段二第一步是启动 `slam` 工作空间并确认点云/里程计频率。
- `ros1_bridge` 默认不桥接自定义消息；规划器自定义 msg（`Bspline`/`DataDisp`）只在同一 ROS 1 域内使用，无需桥接。

### 4.2 Lite3 参数适配清单（`advanced_param.xml`）

默认值面向 Unitree Go2，上 Lite3 前需改写（需你提供实测尺寸/能力）：

| 参数 | 默认(Go2) | 需改为 | 说明 |
|---|---|---|---|
| `grid_map/body_height` | 0.4 | Lite3 站立机身高度 | 决定可通行层高 |
| `grid_map/double_cylinder_radius` | 0.25 | Lite3 半宽 | 自碰撞包络（双圆柱模型） |
| `grid_map/double_cylinder_offset` | 0.18 | Lite3 半长相关 | 前后两个圆柱的中心偏移 |
| `grid_map/obstacles_inflation_z_up/down` | 0.1 / 0.1 | 视地形调 | 垂直方向膨胀 |
| `max_vel` / `max_acc` | 0.75 / 0.5 | Lite3 能力 | 同时影响 `manager/*`、`optimization/*`、`closed_loop_controller/max_vx` |
| `closed_loop_controller/max_vy`、`max_vyaw`、`kp_pos`、`kp_yaw` | 0.35 / 1.0 / 0.8 / 1.5 | 按实机调 | 跟踪增益 |
| `grid_map/cx/cy/fx/fy` | RealSense D435 内参 | 用 103 实际相机（orbbec/realsense）内参 | 仅 depth 模式 |
| `grid_map/need_extrinsic` | 真机为 `true` | 提供雷达→机体外参 | 标定质量直接决定建图质量 |
| `fsm/planning_horizon` | 3.5 | 与雷达探测距离匹配 | |
| 楼梯/台阶 | — | 提高 body/keypoint/path 的 z | README 明确提示 |

### 4.3 执行器接口

- `closed_loop_controller` 输出 `geometry_msgs/Twist` 的 `/cmd_vel`（vx / vy / vyaw）——与 Lite3 现有的 `/cmd_vel` 语义一致，对接成本低。
- 仿真用的 `go2_gait_publisher` / `go2_kinematic_sim` **真机模式下不应参与**，需确认 `is_real_world:=true` 时它们是否被 launch 屏蔽；真机步态由 Lite3 自有控制器负责。
