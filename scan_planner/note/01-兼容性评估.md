## 1. 项目是什么

SCAN-Planner（Spatial Collision-Aware Local planning for Route-Guided Long-Range Quadruped Navigation）是面向**四足机器人**的**空间碰撞感知局部规划器**，基于 EGO-Planner 框架演化，地图表示借鉴 ROG-Map，定位依赖 FAST-LIO2/Elevator-LIO，仿真器改编自 MARSIM + Mockamap。

关键定位（决定部署难度）：它只做**局部规划**，不是完整导航栈：

- 输入：机体里程计（`body_pose_topic`）、传感器位姿（`sensor_pose_topic`）、点云（`cloud_topic`）或深度图（`depth_topic`）、目标点或参考路径
- 输出：B 样条轨迹 `/planning/bspline` → 由 `closed_loop_controller` 转成 `/cmd_vel`（`geometry_msgs/Twist`）

因为输入/输出都是标准 ROS 消息，接入既有机器人栈的成本主要在**话题对齐**和**参数标定**，而不是代码改造。

## 5. 风险登记与降级方案

| ID | 风险 | 等级 | 触发条件 | 降级/处置 |
|---|---|---|---|---|
| R1 | GitHub 直连超时；网络状态随时间波动（01:24 全断、01:47 恢复） | 中 | 裸 `git clone` / 依赖 apt 源异常 | 主路径：走代理 `http://192.168.2.47:7897`（实测 clone 4m29s 成功）；备份路径：`gh-proxy.com` 镜像；兜底：本机下载 + `scp`。另注：清华 `ubuntu-ports` 源 403，建议换 `ports.ubuntu.com`/中科大源 |
| R2 | ROS 1/ROS 2 环境串味（默认 source foxy） | 中 | 直接开 shell 编译 | 用专用 `env.sh`：只 source noetic，并 `unset AMENT_PREFIX_PATH / COLCON_PREFIX_PATH`，清掉 PYTHONPATH 中的 foxy 路径 |
| R3 | GPU 版 local_sensing 构建失败 | 低 | 执行 `catkin_make -DUSE_GPU=ON` | 保持默认 OFF（CPU 版 `pcl_render_node`）。Jetson 提供的是 EGL/GLES，桌面 GL 需 Mesa 栈；且 `libglfw3-dev` 未装，CMake 在缺 glfw3 时会 `FATAL_ERROR` |
| R4 | 编译 OOM / 编译极慢 | 中 | 6 核 6.7 GiB 上并行度过高 | `catkin_make -j2`（保守）→ 观察内存后再提到 `-j3`；确认 swap 在线（`swapon --show`）；不要同时跑 ROS 2 的 transfer 服务做其他编译 |
| R5 | 与现有 `transfer_ros2` 争抢 CPU | 中 | 编译期与推流/监控并存 | 编译时段可临时停 `lite3-monitor.service`；`transfer_ros2` 服务于机器人实时链路，**不要动** |
| R6 | 平台参数不匹配（Go2 vs Lite3） | 高（对真机效果） | 直接上真机 | 改 `advanced_param.xml`：`body_height`、`double_cylinder_radius/offset`、`max_vel/max_acc`、相机内参、外参 `need_extrinsic` |
| R7 | `/cmd_vel` 命名冲突 | 高（对真机安全） | 规划器 ROS 1 侧发 `/cmd_vel`，桥到 ROS 2 会撞上现有 `/cmd_vel` | ROS 1 侧重映射为 `/scan_planner/cmd_vel`，经人工确认后再桥接到机器人指令口；**首次联调务必抬起机器人 / 限速** |
| R8 | 缺少 LIO 输入（faster_lio 未运行） | 中 | 真机联调时 | 实测当前 ROS 2 话题列表里没有 faster_lio 的 `/Odometry`、`/cloud_registered` → 阶段二需先启动 `slam` 工作空间的 faster_lio |
| R9 | ROS 2 版不可用 | — | 想用 `ros2-community` 分支 | 该分支要求 Ubuntu 22.04 + Humble + C++17，103 是 20.04 + Foxy，**不可用**。若要 ROS 2 原生，需自行从 Humble 版回迁到 Foxy（C++17→14、rclcpp API 差异），工作量中高 |
| R10 | RViz 无法在本地显示 | 低 | 103 无桌面会话 | 用 `rostopic`/`rosnode` 做无头验证；可视化改用 103 上已有的 `/home/test/foxglove` 或 X11 转发 |

## 6. 明确结论

1. **能部署。** 运行环境（OS、ROS、编译器、第三方库、catkin 组件）与项目要求逐项命中，源码无架构阻断，磁盘与内存足够。
2. **部署可在线进行。** 走代理 `http://192.168.2.47:7897` 直接在 103 上 clone（实测 4m29s）；离线 scp 作为网络再次劣化时的兜底。依赖已齐，无需联网安装。
3. **第一步只做"编译 + 自带仿真冒烟"。** 该路径不依赖真机传感器、不改动现有 ROS 2 服务，可安全验证兼容性。
4. **真机接入是独立阶段。** 需要解决 ROS 1↔ROS 2 桥接、faster_lio 启动、Lite3 参数与指令口三件事；在此之前不要下发任何运动指令。
